Ключевые акценты:
— «Почему React?» идёт сразу после знакомства с библиотекой. 44,7% — доля 23 678 ответивших на вопрос о веб-технологиях в Stack Overflow Developer Survey 2025, а не доля всех разработчиков или компаний. Диаграмма проверена в браузере.
— На «Почему React?» приведены российские компании: Яндекс, Иви, МТС Web Services, а также вакансии Росгосстраха. Вакансия Яндекса архивная и подтверждает стек команды, не текущий найм. В раскрытии — ссылки на источники. В примерах компаний используем только российские компании.
— До «Какой инструмент разберём?» не называем React.
— Корзина одинакова на первых слайдах и в итоговом сравнении. На слайде с HTML пояснение querySelector/textContent скрыто.
— «Как выглядит весь код корзины?» — отдельный справочный слайд с живой корзиной. Кнопки добавления, скидки, новой цены и сброса подсвечивают связанные строки и прокручивают код к обработчику. Затем выбрать «Пересчёт и DOM», чтобы перейти к updateView и зависимым записям. Можно отдельно подсветить зависимости count и total. Не читать все строки подряд.
— В путях решения по умолчанию выбран первый вариант. Для общей функции показать 2 → 5 → 16 полей; большая версия содержит 52 строки. Для модулей сравнить 2 → 4 → 6 получателей данных.
— Аналогия стройки: библиотека — дрель, молоток и уровень, которые берём по своему плану; фреймворк — готовый каркас и порядок работ, куда добавляем свои части. В коде мы вызываем библиотеку, а фреймворк вызывает наш код в предусмотренных местах. Затем показываем абстракцию в коде и подробнее разбираем различия.
— React берёт на себя вычисление описания интерфейса и применение изменений в DOM. Данные и правила приложения остаются нашей ответственностью.
— Обычное дерево и дерево компонентов имеют одинаковую структуру. Нажатия подсвечивают соответствующие узлы и области страницы; это не обязательно двоичное дерево.
— В JSX сначала определение, затем вставка выражений и className.
— После props показать поток вниз. Потребитель props читает их, новые значения передаёт родитель.
— В эксперименте с локальной переменной ответ появляется после трёх кликов. Затем: простой смысл рендера → необходимость памяти между вызовами → определение state → разбор useState → работающий счётчик. До разбора useState не показываем его запись и setCount.
— На первом слайде о рендере меняем переданные props: одна функция даёт результат для разных данных. Рендер вычисляет описание интерфейса, затем React меняет нужные элементы страницы; это не перезагрузка всей страницы.
— В учебной модели памяти сначала запоминаем 1 и вызываем компонент снова, затем повторяем вызов: он опять получает 1. Сравниваем с let count = 0, которая создаётся заново при каждом вызове. Модель не показывает внутреннее устройство React.
— Подробный разбор рендера расположен после работающего счётчика с useState; затем карта setCount связывает состояние, вызов компонента и обновление DOM.
— Карты рендера и setCount — замедленные учебные модели, а не внутренний отладчик React. Шаги можно проходить кнопкой или выбирать на карте.
— История count показывает первый показ и каждое обновление состояния в простом счётчике без StrictMode. Это не утверждение о количестве внутренних вызовов в любом React-приложении.
— В props/state две карточки: изменение названия первой сохраняет её счётчик, вторая независима. Создание компонентов заново обнуляет обе.
— В callback-схеме props идут вниз; вверх показан вызов переданной функции, а не обратное изменение props.
— S из SOLID: общий владелец состояния связывает части; изменение оформления сводки относится к ShopHeader. Это не правило о размере компонента.
— В финальном сравнении код обеих версий содержит добавление и сброс.
— После итогового сравнения задаём вопрос «А как запустить весь этот код?». Даём аудитории предложить ответ, затем раскрываем «Собрать наш проект».
— На слайде «Какой сборщик будем использовать?» сначала называем Vite, затем сравниваем два блока: build для публикации и dev с быстрыми обновлениями во время работы.
— Node.js — среда выполнения JavaScript вне браузера; npm устанавливает пакеты и запускает скрипты. Сразу после вопроса о запуске объясняем установку Node.js LTS вместе с npm и проверки node -v / npm -v.
— На слайде о сборщике каждый этап подсвечивает свой блок. На первом показываем стрелки index.html → App.jsx → ProductCard.jsx / app.css; на втором — JSX → JavaScript; на третьем — файлы dist. Этапы выбираются кнопкой или заголовками блоков.
— Вопрос о запуске → Node.js и npm → сборщик → преобразование JSX → Vite → команды проекта. Команды и этапы показаны как модель, терминал на устройствах студентов не запускается.

Темп:
Короткие вводные слайды служат переходами, а не отдельными длинными темами.
